أهداف التعلم

اشرح نموذج العميل والخادم ودورة الطلب والاستجابة.

ميّز بين HTTP وHTTPS، واستخدم GET وPOST في سياقات مناسبة.

فسّر رموز حالة HTTP الشائعة، واشرح دور API وJSON في تبادل البيانات.

صمّم طريقة اتصال مناسبة لمهمة في تطبيق ويب، وبرّر اختيارك.

في الدرس 3-1 تعلمت أن الواجهة الأمامية والواجهة الخلفية تتعاونان لتنفيذ طلب المستخدم. في هذا الدرس ستتعلم كيف تنتقل الطلبات والاستجابات بين العميل والخادم.

عندما تنقر على رابط أو تبدأ بحثًا، يطلب المتصفح غالبًا البيانات التي يحتاجها من خدمة على خادم عبر الشبكة. المتصفح هنا عميل (client) يرسل طلبًا، ويعيد الخادم (server) استجابة. وتحدد بروتوكولات مثل HTTP قواعد هذا التبادل. ويُعد نموذج الطلب والاستجابة أساسيًا في كثير من تطبيقات الويب، مع وجود وسائل اتصال أخرى عند الحاجة.

السؤال الرئيس

كيف يتواصل العميل والخادم لتشغيل تطبيق الويب، وما القواعد والرسائل التي يستخدمانها؟

خريطة الدرس

الفكرة الأساسية:

تعمل تطبيقات الويب من خلال إرسال العميل للطلبات، وإرجاع الخادم للاستجابات، باستخدام بروتوكولات (HTTP/HTTPS) وغالبًا واجهات برمجة تتبادل البيانات بصيغ مثل JSON.

المفاهيم الأساسية:

مصطلحات أساسية

العميل – الجانب الذي يطلب البيانات أو المعالجة.
الخادم – الجانب الذي يعالج الطلبات ويعيد الاستجابات.

1العميل والخادم

1

العميل: برنامج أو جهاز يرسل طلبًا إلى خدمة أخرى؛ ومن أمثلته متصفح الويب وتطبيق الهاتف.

2

الخادم: الجانب الذي يستقبل الطلبات من العملاء، ويعالجها، ويعيد الاستجابات.

3

تعتمد كثير من تطبيقات الويب على إرسال العميل طلبًا وإعادة الخادم استجابة.

2HTTP وHTTPS

1

HTTP (بروتوكول نقل النص التشعبي): بروتوكول يستخدم لتبادل الرسائل بين عميل وخادم على الويب.

2

HTTPS: استخدام HTTP عبر اتصال TLS (Transport Layer Security) آمن. يساعد TLS على حماية سرية الاتصال وسلامته، وعلى مصادقة الخادم، بحيث لا يستطيع المتجسس قراءة المحتوى أو تعديله بسهولة أثناء النقل.

3

المواقع التي تبدأ عناوينها بـ"https://" تستخدم اتصال HTTPS.

https://school.example.eg

توقف وفكر

لماذا يجب أن تستخدم صفحة تسجيل الدخول HTTPS بدلًا من HTTP العادي؟

صفحة تسجيل الدخول ترسل بيانات حساسة مثل كلمة المرور. HTTPS يحمي سرية الاتصال وسلامته، فلا يستطيع المتجسس قراءة هذه البيانات أو تعديلها بسهولة أثناء النقل. جرّب التبديل بين HTTP وHTTPS في المشهد أعلاه.

3طلبات HTTP والاستجابات

1

تتضمن الطلبات المرسلة من العميل إلى الخادم معلومات تسمى طريقة طلب HTTP توضح "نوع العملية المطلوبة".

2

تتضمن الاستجابات المرسلة من الخادم إلى العميل رقمًا يشير إلى نتيجة المعالجة. يسمى رمز حالة HTTP. فيما يلي بعض الأمثلة النموذجية.

4واجهة برمجة التطبيقات (API)

1

واجهة برمجة التطبيقات (API): مجموعة قواعد واضحة تسمح لبرنامج بطلب بيانات أو وظائف من برنامج آخر.

2

قد ترسل الواجهة الأمامية طلبات إلى خدمة خلفية عبر API وتستقبل منها البيانات.

3

قد تعيد API بيانات بصيغة JSON (JavaScript Object Notation)، وهي صيغة نصية شائعة لتمثيل وتبادل البيانات المهيكلة باستخدام كائنات ومصفوفات وقيم بسيطة، وتدعمها لغات وأدوات برمجية كثيرة.

{
  "name": "Salma",
  "age": 16,
  "skills": ["HTML", "JavaScript"],
  "address": { "city": "Cairo" }
}

الفكرة الرئيسة

يتواصل تطبيق الويب كتبادل منظم: يطلب العميل ويستجيب الخادم، باستخدام بروتوكول (HTTP/HTTPS)، وطريقة طلب (GET/POST)، ورمز حالة، وغالبًا واجهة برمجة تطبيقات تعيد البيانات بصيغة JSON.
